# Лабораторна 3 — частина студента 1

Початкова версія: OnlineTesting, коміт `302f7e1` (`origin/main` на момент підготовки). Архів містить **лише файли вашої частини**. Розпакуйте у корінь репозиторію зі збереженням каталогів. Не видаляйте інші файли проєкту. Архів студента 2 можна накладати в будь-якому порядку: спільних шляхів немає.

## Що зроблено

- `docker-compose.yml`: три ізольовані API-процеси зі спільною PostgreSQL; зовні відкрито тільки один порт Nginx.
- `backend/OnlineTesting.Api/Program.cs`: readiness `/health` із реальною перевіркою БД та `X-Instance-ID`.
- `frontend/nginx.conf`: Round Robin, повтор безпечних запитів на інший вузол, пасивне виключення недоступного upstream.
- `docs/architecture.md`: C4-схема масштабованого стенду та єдині точки відмови.
- `scripts/verify-lab3-platform.ps1`: перевірка трьох вузлів, аварійної зупинки одного та повернення до пулу.

## Як перевірити свою частину

У `.env` має бути `DB_PASSWORD`. Потрібні Docker Desktop та PowerShell 7.

```powershell
docker compose up -d --build
docker compose ps
pwsh -NoProfile -File scripts/verify-lab3-platform.ps1
```

У `docker compose ps` лише `frontend` повинен мати порт хоста. Скрипт має завершитися `PASS`. Не запускайте його одночасно з експериментом студента 2, бо обидва тимчасово зупиняють вузли.

У Windows PowerShell 5.1 команда `pwsh` може бути відсутня: встановіть PowerShell 7 або запустіть його повним шляхом. Запуск із поточного каталогу скрипта через `powershell -File` не підходить, бо в об'єднаній частині використано паралельні команди PowerShell 7.

Після об'єднання обох частин запускайте повні перевірки з розділу 12 `README.md`.
