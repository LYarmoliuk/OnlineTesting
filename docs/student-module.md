# Модуль проходження тестів — учасник №2

## 1. Призначення модуля

Модуль проходження тестів системи OnlineTesting забезпечує створення спроб тестування, збереження відповідей студентів, автоматичне обчислення результатів та перегляд отриманих балів.

**Використані технології:**
- ASP.NET Core 10 — REST API.
- Entity Framework Core — доступ до бази даних.
- PostgreSQL 17 — збереження спроб і відповідей.
- Vue 3 + TypeScript — інтерфейс студента.
- Docker Compose — запуск компонентів системи.

## 2. Сутності модуля

### TestAttempt

Сутність представляє окрему спробу проходження тесту студентом.

Основні дані:
- Ідентифікатор спроби.
- Посилання на тест.
- Токен доступу до спроби.
- Стан проходження.
- Час початку та завершення.
- Набрані бали.

Один тест може мати багато спроб проходження.

### StudentAnswer

Сутність представляє відповідь студента на конкретне запитання в межах спроби.

Основні дані:
- Ідентифікатор відповіді.
- Посилання на спробу.
- Посилання на запитання.
- Посилання на вибраний варіант відповіді.

Одна спроба може містити багато відповідей.

Сутності Test, Question і AnswerOption реалізуються в інших частинах системи та використовуються модулем студента.

## 3. REST API

| HTTP-метод | Endpoint | Призначення |
|---|---|---|
| POST | `/api/tests/{testId}/attempts` | Почати проходження тесту |
| GET | `/api/attempts/{attemptId}` | Отримати інформацію про спробу |
| PUT | `/api/attempts/{attemptId}/answers` | Зберегти відповідь студента |
| POST | `/api/attempts/{attemptId}/submit` | Завершити спробу та обчислити результат |
| GET | `/api/attempts/{attemptId}/result` | Переглянути результат |

Для доступу до спроби після її створення використовується HTTP-заголовок `X-Attempt-Token`.

Приклад тіла запиту для збереження відповіді:

```json
{
  "questionId": 1,
  "selectedOptionId": 2
}
```

## 4. Алгоритм проходження тесту

1. Студент починає проходження опублікованого тесту.
2. Backend перевіряє, чи тест містить коректні запитання та варіанти відповідей.
3. Створюється запис TestAttempt і генерується токен доступу.
4. Студент отримує запитання та варіанти без позначення правильних відповідей.
5. Студент вибирає варіанти; відповіді зберігаються як StudentAnswer.
6. Після завершення тесту backend перевіряє вибрані варіанти.
7. Розрахований результат зберігається в TestAttempt.
8. Студент переглядає кількість набраних балів.

## 5. Автоматичне оцінювання

Для кожного запитання визначається, чи відповідає вибраний студентом варіант правильному варіанту.

Якщо відповідь правильна, до загального результату додається кількість балів, призначена запитанню.

**Формула:**

`Score = Σ Points(Question), якщо відповідь правильна`

`MaxScore = Σ Points(Question) для всіх запитань тесту`

Неправильна або відсутня відповідь не додає балів.

Повторне надсилання запиту завершення вже завершеної спроби не повинно призводити до повторного нарахування балів.

## 6. Валідація та обробка помилок

Під час створення спроби перевіряється, що:
- тест опублікований;
- тест містить запитання;
- кожне запитання має щонайменше два варіанти;
- кожне запитання має рівно одну правильну відповідь.

Під час збереження відповіді перевіряється доступ до спроби за токеном і відповідність вибраного варіанта запитанню.

Після завершення спроби редагування відповідей не допускається.

## 7. Інтерфейс студента

Інтерфейс реалізований на Vue 3 і TypeScript.

Основні можливості:
- Початок проходження тесту.
- Перегляд запитань і варіантів.
- Вибір і збереження відповідей.
- Відображення прогресу проходження.
- Завершення тесту.
- Перегляд результату.

У Docker інтерфейс доступний за адресою `http://localhost:8081/take-test`.

## 8. Інтеграція з базою даних і Docker

Для збереження даних використовується PostgreSQL 17.

Entity Framework Core виконує операції читання та запису сутностей TestAttempt і StudentAnswer.

Docker Compose запускає API, PostgreSQL та frontend. Для бази даних використовується іменований том `postgres_data`, який забезпечує збереження даних після перезапуску контейнера.

## 9. Потенційні вузькі місця

### 9.1. Одночасне збереження відповідей

**Компонент:** ASP.NET Core API / PostgreSQL.

**Причина:** велика кількість студентів одночасно надсилає запити PUT для збереження відповідей.

**Симптоми:** зростання часу відповіді API, черги запитів до БД, підвищене навантаження на операції запису.

**Можливе покращення:** оптимізація SQL-запитів, індекси та налаштування пулу підключень.

### 9.2. Одночасне завершення тестів

**Компонент:** ASP.NET Core API.

**Причина:** багато студентів одночасно завершують тест, через що API читає відповіді та обчислює результати.

**Симптоми:** збільшення затримки endpoint `/submit`, підвищення використання CPU та кількості запитів до БД.

**Можливе покращення:** ефективне завантаження потрібних даних та зменшення кількості звернень до БД.

### 9.3. Обмеження одного екземпляра PostgreSQL

**Компонент:** PostgreSQL.

**Причина:** усі спроби та відповіді зберігаються в одному екземплярі бази даних.

**Симптоми:** повільні SQL-запити, високий I/O, очікування вільних підключень.

**Можливе покращення:** індексування зовнішніх ключів, аналіз планів запитів і масштабування ресурсів БД.

Наведені проблеми є **потенційними**; фактичні граничні показники навантаження не вимірювалися.
